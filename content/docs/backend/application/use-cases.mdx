Los casos de uso orquestan las operaciones del sistema. Reciben un DTO de
entrada, ejecutan la lógica usando los puertos y devuelven un DTO de salida.

Todos viven en el paquete `src/app/application/use_cases/`.

## Estructura común

Todos siguen el mismo patrón de orquestación pura:

```python
class XxxUseCase:
    def __init__(self, port1: Port1, port2: Port2) -> None:
        self.port1 = port1
        self.port2 = port2

    async def execute(self, request: XxxRequest) -> XxxResponse:
        # 1. Validar (usar value objects del dominio)
        # 2. Operar (usar UoW, repositorio, servicios)
        # 3. Retornar DTO
```

## Flujo Onboarding: `RegisterUserUseCase`

En un modelo multi-tenant SaaS, el registro de un nuevo usuario ejecuta un flujo de **Onboarding** en una sola transacción atómica:
1. Valida que el email no esté registrado globalmente.
2. Genera un `Slug` para la empresa y valida su unicidad.
3. Crea la entidad `Company`.
4. Crea la entidad `User` vinculada a la empresa con contraseña hasheada.
5. Crea un rol **Administrador** por defecto con todos los permisos concedidos.
6. Asigna el rol al usuario creado.
7. Emite los tokens JWT iniciales.

```python
class RegisterUserUseCase:
    """Caso de uso para registrar un nuevo usuario en el sistema, creando su empresa y rol administrador."""

    def __init__(
        self,
        uow: UnitOfWorkPort,
        hasher: PasswordHasherPort,
        token_service: TokenServicePort,
    ) -> None:
        self.uow = uow
        self.hasher = hasher
        self.token_service = token_service

    async def execute(self, request: RegisterUserRequest) -> AuthTokensDTO:
        email = Email(value=request.email)
        plain_password = PlainPassword(value=request.password)

        async with self.uow:
            # 1. Verificar si el email ya está registrado
            existing_user = await self.uow.users.get_by_email(email)
            if existing_user:
                raise UserAlreadyExistsError(
                    f"El correo electrónico '{request.email}' ya está registrado."
                )

            # 2. Generar slug único para la empresa
            slug = Slug.from_name(request.company_name)
            existing_company = await self.uow.companies.get_by_slug(slug)
            if existing_company:
                raise CompanySlugExistsError(
                    f"El slug '{slug.value}' generado para la empresa ya existe."
                )

            # 3. Crear empresa
            company = Company.create(
                nombre=request.company_name, slug=slug, email_contacto=request.email
            )
            await self.uow.companies.save(company)

            # 4. Crear usuario vinculado a la nueva empresa
            hashed_val = self.hasher.hash(plain_password.value)
            hashed_password = HashedPassword(value=hashed_val)
            user = User.register(
                email=email,
                hashed_password=hashed_password,
                empresa_id=company.id,
                nombre=request.nombre,
                telefono=request.telefono,
            )
            await self.uow.users.save(user)

            # 5. Crear rol Administrador por defecto con todos los permisos
            admin_role = Role.create_admin(empresa_id=company.id)
            await self.uow.roles.save(admin_role)

            # 6. Asignar el rol al usuario creado
            await self.uow.roles.assign_to_user(admin_role.id, user.id)

            await self.uow.commit()

            # Generar tokens
            access_token = await self.token_service.generate_access_token(str(user.id))
            refresh_token = await self.token_service.generate_refresh_token(str(user.id))

            return AuthTokensDTO(access_token=access_token, refresh_token=refresh_token)
```

## Casos de Uso del Módulo Auth

- `LoginUserUseCase`: Valida las credenciales del usuario, registra el login en la entidad (emitiendo `UserLoggedIn`) y genera los tokens.
- `RefreshTokenUseCase`: Decodifica el refresh token, lo revoca en Redis (blocklist con rotación), verifica que el usuario esté activo y emite un nuevo par de tokens.
- `LogoutUserUseCase`: Revoca el token de acceso pasándolo a la blocklist de Redis.
- `GetCurrentUserUseCase`: Obtiene los datos del usuario en sesión actual.

---

## Casos de Uso de Negocio (Multi-Tenant y RBAC)

- **Company**: Permite a usuarios autorizados gestionar los datos del tenant.
- **Role**: Permite la creación y actualización de roles con permisos granulares por módulo, y las acciones de asignación y revocación a usuarios específicos.
- **Location**: Permite estructurar la distribución física de la empresa. La eliminación de ubicaciones valida que no existan ciclos jerárquicos.
- **Asset**: Permite gestionar los activos físicos, filtrando los listados por empresa, ubicación y estado.
