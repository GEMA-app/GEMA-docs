Los schemas son modelos Pydantic que definen el formato de entrada y salida
de la API según el estándar JSON:API.

## Schemas base

Archivo: `src/app/presentation/api/v1/schemas/jsonapi_base.py`

Contiene los componentes genéricos que se reusan en todos los recursos:

```python
class ResourceIdentifier(BaseModel):
    type: str
    id: str


class LinksObject(BaseModel):
    self: Optional[str] = None
    related: Optional[str] = None


class ErrorObject(BaseModel):
    id: Optional[str] = None
    links: Optional[LinksObject] = None
    status: Optional[str] = None
    code: Optional[str] = None
    title: Optional[str] = None
    detail: Optional[str] = None
    source: Optional[ErrorSource] = None
    meta: Optional[dict[str, Any]] = None


class JsonApiErrorDocument(BaseModel):
    errors: list[ErrorObject]
    meta: Optional[dict[str, Any]] = None
```

| Schema | Propósito |
|---|---|
| `ResourceIdentifier` | Identificador `{type, id}` para relaciones |
| `LinksObject` | Enlaces HATEOAS (`self`, `related`) |
| `ErrorObject` | Error individual con `status`, `code`, `title`, `detail`, `source` |
| `JsonApiErrorDocument` | Documento de error: `{ errors: [...] }` |

## Schemas de auth

Archivo: `src/app/presentation/api/v1/schemas/auth.py`

Siguen una estructura de tres niveles para cada recurso. Se ha modificado el esquema de registro para soportar el onboarding de SaaS:

```python
# 1. Atributos del recurso
class UserAttributes(BaseModel):
    email: str
    nombre: str
    empresa_id: str
    telefono: str | None = None
    is_active: bool
    created_at: datetime
    updated_at: datetime


# 2. Recurso (data)
class UserResource(BaseModel):
    type: str = "users"
    id: str
    attributes: UserAttributes
    links: Optional[LinksObject] = None


# 3. Documento (envoltura)
class UserDocument(BaseModel):
    data: UserResource
    links: Optional[LinksObject] = None
    meta: Optional[dict[str, Any]] = None
```

Para las solicitudes de registro (`RegisterRequest`), se agregaron atributos correspondientes a la creación inicial de la empresa del usuario:

```python
class RegisterAttributes(BaseModel):
    email: str = Field(..., description="Correo electrónico para registro")
    password: str = Field(..., description="Contraseña en texto plano")
    nombre: str = Field(..., description="Nombre completo del usuario")
    company_name: str = Field(..., description="Nombre de la empresa a crear")
    telefono: str | None = Field(None, description="Teléfono de contacto")
```

## Nuevos Schemas de Dominio

### Módulo Company (`schemas/company.py`)
Define `CompanyAttributes`, `CompanyResource` y `CompanyDocument` para representar el recurso `companies`.
- Los atributos de entrada para creación/edición validan el nombre de la empresa y correos válidos para el contacto.

### Módulo Role (`schemas/role.py`)
Define el recurso `roles`. Incluye el sub-esquema `PermissionDTO` para estructurar la definición de permisos por módulo del sistema:
```python
class PermissionDTO(BaseModel):
    module: str
    can_view: bool = False
    can_create: bool = False
    can_edit: bool = False
    can_delete: bool = False
```

### Módulo Location (`schemas/location.py`)
Define el recurso `locations`. Los atributos incluyen `parent_id` (de tipo UUID o None). Soporta representación anidada del árbol jerárquico.

### Módulo Asset (`schemas/asset.py`)
Define el recurso `assets` con atributos de negocio: `articulo_id`, `ubicacion_id`, `serial_interno`, `codigo_activo`, `estado` (validado mediante enum), `fecha_adquisicion`, `valor_monetario`, `moneda`.

## Patrón general JSON:API

Cada recurso sigue siempre la misma estructura:

```
Documento (response):      Solicitud (request):
{                          {
  "data": {                  "data": {
    "type": "users",           "type": "users",
    "id": "uuid",              "attributes": { ... }
    "attributes": { ... }    }
  }                         }
}
```

La diferencia es que en las respuestas el recurso tiene `id`, mientras que
en las solicitudes de creación el `id` no se envía (lo genera el servidor).

## Cómo crear schemas nuevos

1. Define los `Attributes` con los campos del recurso.
2. Define el `Resource` con `type`, `id` (si aplica) y `attributes`.
3. Define el `Document` con `data`.
4. Si es una solicitud, define el `Request` con `data.resource`.
5. Reusa `LinksObject` y `ResourceIdentifier` de `jsonapi_base.py`.
