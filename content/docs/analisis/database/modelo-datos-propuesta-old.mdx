# Propuesta de modelo de datos

Este documento describe el esquema v0.1 de GEMA, tal como quedó
implementado tras las mejoras aplicadas al MVP. Incluye la
normalización de tipos de datos, enums nativos, timestamps de
auditoría en todas las tablas y la trazabilidad de aprobaciones en
órdenes de trabajo.

> [!IMPORTANT]
> Esta es la versión consolidada del esquema v0.1. Los cambios
> incluyen: eliminación de `frecuencia_tipo` en planes de
> mantenimiento, reemplazo de `validado_gerencia` por trazabilidad
> de aprobaciones, renombre de tablas para consistencia (`reportes_falla`
> → `reportes_fallas`), paso de `text` a `varchar` y enums nativos,
> y timestamps `created_at`/`updated_at` con `default: now()` en
> todas las tablas.
>
> Quedan diferidos a fases posteriores: multimoneda con histórico de
> tasas, auditoría granular por campo, KPIs precalculados y alertas.

## Enums del sistema

Se adoptan enums nativos de PostgreSQL para garantizar integridad
referencial a nivel de motor.

| Enum | Valores | Cambio respecto al MVP |
|---|---|---|
| `estado_activo` | `operativo`, `en_mantenimiento`, `fuera_de_servicio`, `dado_de_baja` | Sin cambios |
| `tipo_mantenimiento` | `preventivo`, `correctivo`, `predictivo` | Sin cambios |
| `estado_orden_trabajo` | `abierta`, `en_proceso`, `pausada`, `cerrada`, `cancelada` | Renombrado de `estado_ot` |
| `tipo_ubicacion` | `sede`, `planta`, `area`, `seccion` | Nuevo (antes `varchar` libre) |
| `modulo_permiso` | `activos`, `mantenimiento`, `inventario`, `reportes`, `administracion` | Nuevo (antes `varchar` libre) |

El enum `frecuencia_tipo` se eliminó. Su función la cubre
`intervalo_dias` como fuente única de verdad.

El modelo de permisos se rediseñó: ahora los permisos se asignan
directamente a cada rol con flags booleanos por operación CRUD.

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|

## Planificación de mantenimiento preventivo

Se eliminó el campo `frecuencia` (enum redundante con
`intervalo_dias`). `intervalo_dias` pasa a ser obligatorio como
fuente única de verdad. Se agrega `planes_ejecuciones` para
vincular cada plan con las órdenes de trabajo que generó.

### planes\_mantenimiento

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|
| `id` | integer | pk, autoincremental | Identificador único |
| `activo_id` | integer | ref: activos.id, not null | Activo al que aplica |
| `tecnico_responsable_id` | integer | ref: usuarios.id | Técnico asignado |
| `nombre` | varchar | not null | Nombre del plan |
| `tipo` | tipo_mantenimiento | not null | Tipo de mantenimiento |
| `intervalo_dias` | integer | not null | Días entre ejecuciones (fuente única) |
| `proxima_ejecucion` | date | not null | Fecha de la próxima revisión |
| `descripcion_tareas` | text | | Detalle de las tareas a realizar |
| `activo` | boolean | default: true | Si el plan está vigente |
| `created_at` | timestamp | default: now() | Fecha de creación |
| `updated_at` | timestamp | default: now() | Última actualización |

### planes\_ejecuciones

Tabla que vincula cada plan con las órdenes de trabajo que generó.

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|
| `id` | integer | pk, autoincremental | Identificador único |
| `plan_id` | integer | ref: planes_mantenimiento.id, not null | Plan que originó la OT |
| `ot_id` | integer | ref: ordenes_trabajo.id, not null | Orden de trabajo generada |
| `fecha_ejecucion` | timestamp | default: now() | Cuándo se ejecutó |
| `observaciones` | text | | Notas sobre la ejecución |
| `created_at` | timestamp | default: now() | Fecha de registro |
| `updated_at` | timestamp | default: now() | Última actualización |

## Reportes de falla y órdenes de trabajo

La tabla `reportes_falla` se renombra a `reportes_fallas` (plural
consistente). En las órdenes de trabajo, `validado_gerencia`
(booleano) se reemplaza por `validado_por_id` + `fecha_validacion`
para trazabilidad de aprobaciones.

### reportes\_fallas

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|
| `id` | integer | pk, autoincremental | Identificador único |
| `activo_id` | integer | ref: activos.id, not null | Activo afectado |
| `reportado_por_id` | integer | ref: usuarios.id | Quién reporta la falla |
| `descripcion` | text | not null | Descripción del problema |
| `fecha_reporte` | timestamp | default: now() | Cuándo se reportó |
| `created_at` | timestamp | default: now() | Fecha de registro |
| `updated_at` | timestamp | default: now() | Última actualización |

### ordenes\_trabajo

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|
| `id` | integer | pk, autoincremental | Identificador único |
| `codigo_ot` | varchar | unique, not null | Código legible (ej: `OT-2026-0001`) |
| `activo_id` | integer | ref: activos.id, not null | Activo intervenido |
| `reporte_id` | integer | ref: reportes_fallas.id, null | Origen si es correctivo |
| `plan_id` | integer | ref: planes_mantenimiento.id, null | Origen si es preventivo |
| `supervisor_id` | integer | ref: usuarios.id | Supervisor a cargo |
| `tipo` | tipo_mantenimiento | not null | Tipo de mantenimiento |
| `estado` | estado_orden_trabajo | default: abierta | Estado actual de la orden |
| `fecha_apertura` | timestamp | | Cuándo se abrió la OT |
| `fecha_inicio_trabajo` | timestamp | | Cuándo arrancó el trabajo |
| `fecha_cierre` | timestamp | | Cuándo se cerró la OT |
| `descripcion_trabajo` | text | | Detalle del trabajo realizado |
| `costo_estimado` | numeric(12,2) | | Costo presupuestado |
| `costo_real` | numeric(12,2) | | Costo final |
| `moneda` | varchar(3) | default: 'USD' | Divisa de los costos |
| `validado_por_id` | integer | ref: usuarios.id, null | Usuario que aprobó la OT |
| `fecha_validacion` | timestamp | | Cuándo se aprobó |
| `created_at` | timestamp | default: now() | Fecha de creación |
| `updated_at` | timestamp | default: now() | Última actualización |

### tecnicos\_ordenes\_trabajo

Técnicos asignados a una orden de trabajo (relación muchos a

| Campo | Tipo | Restricciones | Descripción |
|---|---|---|---|

## Resumen de relaciones

```
roles_usuarios >── usuarios
roles_usuarios >── roles ──< permisos

ubicaciones ──< ubicaciones (self-ref, jerarquía)

categorias_articulos ──< articulos_catalogo ──< activos

activos ──< planes_mantenimiento ──< planes_ejecuciones >── ordenes_trabajo
activos ──< reportes_fallas ──< ordenes_trabajo
activos ──< logs_estados_activos

ordenes_trabajo ──< tecnicos_ordenes_trabajo >── usuarios
ordenes_trabajo ──< logs_estados_ordenes_trabajo
ordenes_trabajo ──< entradas_inventario

proveedores ──< inventario_repuestos ──< entradas_inventario
```

## Cambios respecto al MVP

| Categoría | Detalle |
|---|---|
| Enums nuevos | `tipo_ubicacion`, `modulo_permiso` |
| Enums renombrados | `estado_ot` → `estado_orden_trabajo` |
| Enums eliminados | `frecuencia_tipo` (reemplazado por `intervalo_dias` not null) |
| Tablas nuevas | `planes_ejecuciones`, `logs_estados_ordenes_trabajo` |
| Tablas renombradas | `auditoria_sistema` → `auditorias_sistema`, `reportes_falla` → `reportes_fallas` |
| Modelo de permisos | Rediseñado: permisos por rol con flags CRUD (`puede_ver`, `puede_crear`, `puede_editar`, `puede_eliminar`) |
| Trazabilidad | `validado_gerencia` → `validado_por_id` + `fecha_validacion` |
| Integridad | Campos `text` → `varchar` o enums nativos en todas las tablas |
| Timestamps | Todas las tablas ganan `created_at` y `updated_at` con `default: now()` |

### Diferido a fases posteriores

| Funcionalidad | Detalle |
|---|---|
| Multimoneda | `tasas_cambio` + campos `*_original` / `*_base` en tablas monetarias |
| Auditoría granular | `auditorias_cambios` (seguimiento campo por campo) |
| KPIs | `kpis_activos_mensuales`, `kpis_tecnicos_mensuales` |
| Alertas | Tabla `alertas` con tipos polimórficos |
| Intervenciones técnicas | Tablas `intervenciones_tecnicas` y `repuestos_utilizados` |
