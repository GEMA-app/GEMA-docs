---
title: Excepciones de dominio
description: Jerarquía de DomainException y su mapeo a respuestas HTTP con formato JSON API
---

Las excepciones de dominio representan errores que el negocio puede
producir. Se lanzan desde las entidades y los value objects, nunca desde la
infraestructura ni la presentación.

## Jerarquía

Todas las excepciones viven en `src/app/domain/exceptions.py`:

```
DomainException          ← Base de todas
└── AuthException        ← Base del módulo de autenticación
    ├── WeakPasswordError
    ├── InvalidEmailError
    ├── UserAlreadyExistsError
    ├── InvalidCredentialsError
    ├── UserInactiveError
    └── InvalidTokenError
```

```python
class DomainException(Exception):
    """Clase base para todas las excepciones del dominio."""
    pass


class AuthException(DomainException):
    """Clase base para excepciones del módulo de autenticación."""
    pass


class WeakPasswordError(AuthException):
    """Lanzada cuando la contraseña no cumple con las reglas de complejidad."""
    pass


class InvalidEmailError(AuthException):
    """Lanzada cuando el correo electrónico tiene un formato inválido."""
    pass


class UserAlreadyExistsError(AuthException):
    """Lanzada cuando se intenta registrar un email ya registrado."""
    pass


class InvalidCredentialsError(AuthException):
    """Lanzada cuando el correo o la contraseña son incorrectos."""
    pass


class UserInactiveError(AuthException):
    """Lanzada cuando un usuario inactivo intenta una acción."""
    pass


class InvalidTokenError(AuthException):
    """Lanzada cuando un token es inválido, revocado o expiró."""
    pass
```

## Mapeo a respuestas HTTP

El archivo `src/app/presentation/exception_handlers.py` traduce cada
excepción de dominio a un código HTTP y un código interno en formato
JSON:API:

| Excepción | HTTP status | Código interno | Dónde se lanza |
|---|---|---|---|
| `WeakPasswordError` | 422 | `ERR_WEAK_PASSWORD` | `PlainPassword.__post_init__` |
| `InvalidEmailError` | 422 | `ERR_INVALID_EMAIL` | `Email.__post_init__` |
| `UserAlreadyExistsError` | 409 | `ERR_USER_ALREADY_EXISTS` | Caso de uso `register_user` |
| `InvalidCredentialsError` | 401 | `ERR_INVALID_CREDENTIALS` | Caso de uso `login_user` |
| `UserInactiveError` | 403 | `ERR_USER_INACTIVE` | `User.login()` |
| `InvalidTokenError` | 401 | `ERR_INVALID_TOKEN` | Casos de uso que decodifican tokens |
| `RequestValidationError` (Pydantic) | 422 | `ERR_VALIDATION` | Schemas de presentación |

> [!TIP]
> Si necesitas una excepción nueva, créala heredando de `AuthException` (o
> de `DomainException` si no pertenece a autenticación) y agrega un `elif`
> en `domain_exception_handler()` dentro de
> `presentation/exception_handlers.py`.

## ¿Por qué excepciones propias?

Podrías lanzar `HTTPException` directamente desde el dominio, pero eso
acoplaría el dominio a Starlette/FastAPI. Usar excepciones propias mantiene
el dominio puro y permite que la capa de presentación decida cómo
traducirlas.

```
Dominio lanza WeakPasswordError
  → Caso de uso lo propaga
    → Exception handler lo captura
      → Responde HTTP 422 con JSON:API
```

Si mañana cambias FastAPI por otra cosa, el dominio sigue funcionando. Solo
cambias el exception handler.
