Esta página explica cómo se implementan las entidades en GEMA, qué invariantes mantienen y cómo se comportan.

## ¿Qué es una entidad?

Una entidad es un objeto del dominio que tiene **identidad propia**. Dos entidades con los mismos atributos pero diferente identidad son objetos distintos. Las entidades del proyecto viven en el paquete `src/app/domain/entities/`.

<Callout type="info">

La diferencia clave entre una entidad y un value object es la identidad. `User` es entidad porque importa **quién** es (`UserId`). `Permission` es value object (implementado como dataclass inmutable) porque importa **qué** permisos tiene, no quién es.

</Callout>

## La entidad `User`

Representa a un usuario de la plataforma GEMA. Está vinculado a una empresa y tiene roles asociados. Vive en `src/app/domain/entities/user.py`:

```python
class User:
    """Entidad de dominio rica que representa a un usuario en el sistema."""

    def __init__(
        self,
        id: UserId,
        email: Email,
        hashed_password: HashedPassword,
        empresa_id: CompanyId,
        nombre: str,
        telefono: str | None = None,
        is_active: bool = True,
        roles: list[Role] | None = None,
        created_at: datetime | None = None,
        updated_at: datetime | None = None,
    ) -> None:
        self.id = id
        self.email = email
        self.hashed_password = hashed_password
        self.empresa_id = empresa_id
        self.nombre = nombre
        self.telefono = telefono
        self.is_active = is_active
        self.roles = roles or []
        self.created_at = created_at or datetime.now(UTC)
        self.updated_at = updated_at or datetime.now(UTC)
        self._events: list[DomainEvent] = []

    @classmethod
    def register(
        cls,
        email: Email,
        hashed_password: HashedPassword,
        empresa_id: CompanyId,
        nombre: str,
        telefono: str | None = None,
    ) -> "User":
        user_id = UserId(value=uuid.uuid4())
        user = cls(
            id=user_id,
            email=email,
            hashed_password=hashed_password,
            empresa_id=empresa_id,
            nombre=nombre,
            telefono=telefono,
            is_active=True,
            roles=[],
        )
        user._events.append(UserRegistered(user_id=str(user.id), email=user.email.value))
        return user

    def login(self) -> None:
        if not self.is_active:
            raise UserInactiveError(f"El usuario {self.email.value} está inactivo.")
        self._events.append(UserLoggedIn(user_id=str(self.id), email=user.email.value))
```

### Invariantes de `User`
- Un usuario inactivo no puede iniciar sesión.
- Su identificador `id` y su `empresa_id` deben ser VOs de tipo `UserId` y `CompanyId` válidos.

## La entidad `Company` (Tenant)

GEMA es una plataforma multi-tenant aislada. Cada empresa representa un tenant independiente. Vive en `src/app/domain/entities/company.py`:

```python
@dataclass
class Company:
    """Entidad que representa una Empresa (Tenant) en la plataforma GEMA."""

    id: CompanyId
    nombre: str
    slug: Slug
    rif: str | None = None
    email_contacto: str | None = None
    estado: CompanyStatus = CompanyStatus.ACTIVE
    plan_id: uuid.UUID | None = None
    trial_hasta: date | None = None

    @classmethod
    def create(
        cls,
        nombre: str,
        slug: Slug,
        rif: str | None = None,
        email_contacto: str | None = None,
        plan_id: uuid.UUID | None = None,
        trial_hasta: date | None = None,
        estado: CompanyStatus = CompanyStatus.ACTIVE,
    ) -> "Company":
        if not nombre or not nombre.strip():
            raise ValueError("El nombre de la empresa no puede estar vacío.")

        company_id = CompanyId(value=uuid.uuid4())
        company = cls(
            id=company_id,
            nombre=nombre.strip(),
            slug=slug,
            rif=rif,
            email_contacto=email_contacto,
            estado=estado,
            plan_id=plan_id,
            trial_hasta=trial_hasta,
        )
        company._events.append(
            CompanyCreated(
                company_id=str(company.id), nombre=company.nombre, slug=company.slug.value
            )
        )
        return company
```

## La entidad `Role` y el VO `Permission` (RBAC)

El control de acceso basado en roles (RBAC) se maneja a nivel de dominio. Un rol pertenece a una empresa y tiene una lista de permisos para diferentes módulos del sistema. Viven en `src/app/domain/entities/role.py` y `permission.py`:

```python
@dataclass
class Role:
    id: RoleId
    empresa_id: CompanyId
    nombre: str
    descripcion: str
    permisos: list[Permission] = field(default_factory=list)

    def has_permission(self, module: PermissionModule, action: str) -> bool:
        """Verifica si el rol tiene el permiso solicitado para un módulo.
        action: 'view' | 'create' | 'edit' | 'delete'
        """
        for p in self.permisos:
            if p.module == module:
                if action == "view": return p.can_view
                elif action == "create": return p.can_create
                elif action == "edit": return p.can_edit
                elif action == "delete": return p.can_delete
        return False
```

### El Objeto de Valor `Permission`
Es una dataclass inmutable (`frozen=True`) que encapsula los permisos CRUD para un módulo:
```python
@dataclass(frozen=True)
class Permission:
    module: PermissionModule
    can_view: bool = False
    can_create: bool = False
    can_edit: bool = False
    can_delete: bool = False
```

## La entidad `Location` (Ubicaciones Jerárquicas)

Representa las ubicaciones físicas del inventario y los activos. Se organiza como un árbol jerárquico y valida las relaciones entre los tipos de sedes, plantas, áreas y secciones. Vive en `src/app/domain/entities/location.py`:

```python
@dataclass
class Location:
    id: LocationId
    empresa_id: CompanyId
    parent_id: LocationId | None
    nombre: str
    tipo: LocationType
    descripcion: str | None = None

    @staticmethod
    def validate_hierarchy(tipo: LocationType, parent_tipo: LocationType | None) -> None:
        """Valida que la jerarquía de tipos de ubicación sea correcta."""
        if tipo == LocationType.HEADQUARTERS and parent_tipo is not None:
            raise LocationInvalidTypeHierarchyError("Una sede (HEADQUARTERS) no puede tener padre.")
        elif tipo == LocationType.PLANT and parent_tipo != LocationType.HEADQUARTERS:
            raise LocationInvalidTypeHierarchyError("Una planta (PLANT) debe tener una sede (HEADQUARTERS) como padre.")
        elif tipo == LocationType.AREA and parent_tipo != LocationType.PLANT:
            raise LocationInvalidTypeHierarchyError("Un área (AREA) debe tener una planta (PLANT) como padre.")
        elif tipo == LocationType.SECTION and parent_tipo != LocationType.AREA:
            raise LocationInvalidTypeHierarchyError("Una sección (SECTION) debe tener un área (AREA) como padre.")
```

## La entidad `Asset` (Activos Físicos)

Representa un activo físico que está asignado a una ubicación jerárquica y que pertenece al tenant (empresa). Vive en `src/app/domain/entities/asset.py`:

```python
@dataclass
class Asset:
    id: AssetId
    empresa_id: CompanyId
    articulo_id: uuid.UUID
    ubicacion_id: LocationId | None
    serial_interno: str
    codigo_activo: str
    estado: AssetStatus
    fecha_adquisicion: date | None = None
    valor_monetario: float | None = None
    moneda: str = "USD"
```

## Eventos que emite el Dominio

Las entidades acumulan eventos internamente que se recuperan mediante `pull_events()`.

| Entidad | Método / Acción | Evento que emite |
|---|---|---|
| `User` | `User.register()` | `UserRegistered` |
| `User` | `User.login()` | `UserLoggedIn` |
| `Company` | `Company.create()` | `CompanyCreated` |
