# ADR-008: Validación de contraseña antes de hashear (fail-fast)

- **Estado:** Aceptado
- **Fecha:** 2026-05-18

## Contexto

Las contraseñas débiles no deberían llegar al hasher. Es más eficiente y seguro rechazarlas en la capa de dominio, antes de cualquier operación costosa o de infraestructura.

## Decisión

`PlainPassword` valida la fortaleza en `__post_init__()`:

```python
@dataclass(frozen=True)
class PlainPassword:
    value: str

    def __post_init__(self) -> None:
        if len(self.value) < 8:
            raise WeakPasswordError("Mínimo 8 caracteres.")
        if not re.search(r"[A-Z]", self.value):
            raise WeakPasswordError("Debe contener una mayúscula.")
        if not re.search(r"\d", self.value):
            raise WeakPasswordError("Debe contener un número.")
        if not re.search(r"[!@#$%^&*(),.?\":{}|<>\-_]", self.value):
            raise WeakPasswordError("Debe contener un carácter especial.")
```

Si falla la validación, `WeakPasswordError` se propaga al exception handler que responde con 422 y JSON:API.

## Consecuencias

- Las contraseñas débiles nunca se hashean (fail-fast)
- El mensaje de error incluye `source.pointer: /data/attributes/password`
- La validación está en el dominio, no en el schema de presentación
- Cambiar las reglas de fortaleza solo toca un archivo
