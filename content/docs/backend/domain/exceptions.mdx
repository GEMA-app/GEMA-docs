---
title: Excepciones de dominio
description: Jerarquía de DomainException y su mapeo a respuestas HTTP con formato JSON API

Las excepciones de dominio representan errores que el negocio puede
producir. Se lanzan desde las entidades y los value objects, nunca desde la
infraestructura ni la presentación.

## Jerarquía

Todas las excepciones viven en el paquete `src/app/domain/exceptions/`:

```
DomainException                    ← Base de todas
├── AuthException                  ← Base de autenticación y usuarios
│   ├── WeakPasswordError
│   ├── InvalidEmailError
│   ├── UserAlreadyExistsError
│   ├── InvalidCredentialsError
│   ├── UserInactiveError
│   └── InvalidTokenError
├── CompanyException               ← Base del módulo de empresas
│   ├── CompanyNotFoundError
│   └── CompanySlugExistsError
├── RoleException                  ← Base del módulo de roles
│   ├── RoleNotFoundError
│   └── RoleNameExistsError
├── PermissionException            ← Base de autorización
│   └── InsufficientPermissionsError
├── AssetException                 ← Base del módulo de activos
│   ├── AssetNotFoundError
│   ├── AssetCodeExistsError
│   └── AssetSerialExistsError
├── LocationException              ← Base de ubicaciones
│   ├── LocationNotFoundError
│   ├── LocationCircularReferenceError
│   └── LocationInvalidTypeHierarchyError
└── ValidationException            ← Errores de validación generales
```

## Mapeo a respuestas HTTP

El módulo `src/app/presentation/exception_handlers/domain.py` traduce cada
excepción de dominio a un código HTTP y un código interno en formato
JSON:API usando un registro declarativo `_EXCEPTION_MAP`:

| Excepción | HTTP status | Código interno | Dónde se lanza |
|---|---|---|---|
| `WeakPasswordError` | 422 | `ERR_WEAK_PASSWORD` | `PlainPassword.__post_init__` |
| `InvalidEmailError` | 422 | `ERR_INVALID_EMAIL` | `Email.__post_init__` |
| `UserAlreadyExistsError` | 409 | `ERR_USER_ALREADY_EXISTS` | Caso de uso `register_user` |
| `InvalidCredentialsError` | 401 | `ERR_INVALID_CREDENTIALS` | Caso de uso `login_user` |
| `UserInactiveError` | 403 | `ERR_USER_INACTIVE` | `User.login()` |
| `InvalidTokenError` | 401 | `ERR_INVALID_TOKEN` | Casos de uso de autenticación |
| `CompanyNotFoundError` | 404 | `ERR_COMPANY_NOT_FOUND` | Casos de uso de empresas |
| `CompanySlugExistsError` | 409 | `ERR_COMPANY_SLUG_EXISTS` | Caso de uso `create_company` |
| `RoleNotFoundError` | 404 | `ERR_ROLE_NOT_FOUND` | Casos de uso de roles |
| `RoleNameExistsError` | 409 | `ERR_ROLE_NAME_EXISTS` | Caso de uso `create_role` |
| `InsufficientPermissionsError` | 403 | `ERR_INSUFFICIENT_PERMISSIONS` | `RbacAuthorizationService` |
| `AssetNotFoundError` | 404 | `ERR_ASSET_NOT_FOUND` | Casos de uso de activos |
| `AssetCodeExistsError` | 409 | `ERR_ASSET_CODE_EXISTS` | Caso de uso `create_asset` |
| `AssetSerialExistsError` | 409 | `ERR_ASSET_SERIAL_EXISTS` | Caso de uso `create_asset` |
| `LocationNotFoundError` | 404 | `ERR_LOCATION_NOT_FOUND` | Casos de uso de ubicaciones |
| `LocationCircularReferenceError` | 422 | `ERR_LOCATION_CIRCULAR_REFERENCE` | `LocationRepository` (validación de ciclos) |
| `LocationInvalidTypeHierarchyError` | 422 | `ERR_LOCATION_INVALID_TYPE_HIERARCHY` | `Location.validate_hierarchy` |
| `ValidationException` | 422 | `ERR_VALIDATION` | Validaciones generales |
| `RequestValidationError` (Pydantic) | 422 | `ERR_VALIDATION` | Schemas de presentación |

<Callout type="info">

Si necesitas una excepción nueva, créala en su archivo correspondiente dentro del paquete `domain/exceptions/`, re-expórtala en `domain/exceptions/__init__.py` y agrégala al diccionario `_EXCEPTION_MAP` en `presentation/exception_handlers/domain.py`.

</Callout>

## ¿Por qué excepciones propias?

Podrías lanzar `HTTPException` directamente desde el dominio, pero eso
acoplaría el dominio a Starlette/FastAPI. Usar excepciones propias mantiene
el dominio puro y permite que la capa de presentación decida cómo
traducirlas.

```
Dominio lanza WeakPasswordError
  → Caso de uso lo propaga
    → Exception handler lo captura
      → Responde HTTP 422 con JSON:API
```

Si mañana cambias FastAPI por otra cosa, el dominio sigue funcionando. Solo
cambias el exception handler.
