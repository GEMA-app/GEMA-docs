# Modelo de datos GEMA

Este documento describe el esquema de base de datos de GEMA. Sigue un patrón multitenant con esquema compartido: todas las tablas de inquilino llevan `empresa_id` para aislar los datos de cada cliente, con políticas RLS a nivel de base de datos.

---

## Enums del sistema

GEMA define seis enums nativos de PostgreSQL para garantizar integridad referencial a nivel de base de datos.

| Enum | Valores | Descripción |
|---|---|---|
| `estado_activo` | `operativo`, `en_mantenimiento`, `fuera_de_servicio`, `dado_de_baja` | Estados del ciclo de vida de un activo |
| `tipo_mantenimiento` | `preventivo`, `correctivo`, `predictivo` | Clasificación del mantenimiento |
| `estado_orden_trabajo` | `abierta`, `en_proceso`, `pausada`, `cerrada`, `cancelada` | Estados del ciclo de una orden de trabajo |
| `tipo_ubicacion` | `sede`, `planta`, `area`, `seccion` | Niveles jerárquicos de ubicación |
| `modulo_permiso` | `activos`, `mantenimiento`, `inventario`, `reportes`, `administracion` | Módulos del sistema para el RBAC |
| `estado_empresa` | `activa`, `suspendida`, `cancelada` | Estados de la cuenta de un cliente |
| `prioridad_nivel` | `critica`, `alta`, `media`, `baja` | Nivel de urgencia de reportes de fallas |
| `estado_reporte` | `pendiente`, `en_proceso`, `atendido`, `descartado` | Estados de procesamiento de un reporte de falla |

## Capa de inquilino

Todas las tablas siguientes incluyen `empresa_id` como clave foránea a `empresas.id`. Las restricciones `unique` son compuestas con `empresa_id` para permitir que valores idénticos existan en distintos clientes. Cada tabla tiene un índice explícito sobre `empresa_id` para garantizar el rendimiento de las consultas.

## Resumen de relaciones

```
empresas ──< plan_id: planes_suscripcion (contrata un plan)

usuarios ── preferencias_usuarios (relación 1:1)
usuarios ──< roles_usuarios >── roles
roles ──< permisos (CRUD por rol + módulo)

ubicaciones ──< ubicaciones (self-ref, jerarquía)

categorias_articulos ──< articulos_catalogo ──< activos
proveedores ──< inventario_repuestos

activos ──< planes_mantenimiento ──< planes_ejecuciones >── ordenes_trabajo
activos ──< reportes_fallas ──< ordenes_trabajo
activos ──< logs_estados_activos

ordenes_trabajo ──< tecnicos_ordenes_trabajo >── usuarios
ordenes_trabajo ──< intervenciones_tecnicas >── usuarios
intervenciones_tecnicas ──< repuestos_utilizados >── inventario_repuestos
ordenes_trabajo ──< logs_estados_ordenes_trabajo

inventario_repuestos ──< entradas_inventario >── ordenes_trabajo (movimientos)

auditorias_sistema (registro general de acciones)
```

Todas las tablas de inquilino (excepto las intermedias) heredan de `empresas` mediante `empresa_id`.

## Cambios respecto al MVP

| Categoría | Detalle |
|---|---|
| Capa multitenant | Nuevas tablas `empresas` y `planes_suscripcion`; `empresa_id` en todas las tablas de inquilino |
| Enums nuevos | `tipo_ubicacion`, `modulo_permiso`, `estado_empresa`, `prioridad_nivel`, `estado_reporte` |
| Enums nativos | Todos los enums se definen como tipos nativos de PostgreSQL |
| Tablas nuevas | `planes_suscripcion`, `empresas`, `preferencias_usuarios`, `planes_ejecuciones`, `tecnicos_ordenes_trabajo`, `intervenciones_tecnicas`, `repuestos_utilizados`, `logs_estados_ordenes_trabajo` |
| Tablas renombradas | `auditoria_sistema` → `auditorias_sistema`, `reportes_falla` → `reportes_fallas` |
| Firma digital | `validado_gerencia` (boolean) → `validado_por_id` + `fecha_validacion` |
| Frecuencia eliminada | `frecuencia` (enum redundante) eliminado; `intervalo_dias` es not null como única fuente de verdad |
| Integridad | Campos `text` → `varchar` en campos cortos; enums nativos en todas las tablas |
| Timestamps | Todas las tablas ganan `created_at` y `updated_at` con `default: now()` |
| Intervenciones y Repuestos | Incorporación de `intervenciones_tecnicas` y `repuestos_utilizados` para registrar horas hombre, tareas y consumos de materiales. |
| Preferencias de usuario | Incorporación de la tabla `preferencias_usuarios` con relación 1:1 para almacenar preferencias visuales (tema). |

### Funcionalidades diferidas

Las siguientes mejoras identificadas durante el diseño no se incluyen en  y quedan para versiones posteriores:

| Funcionalidad | Descripción |
|---|---|
| Multimoneda | Tabla `tasas_cambio` con histórico de tasas y campos multimoneda en `activos`, `ordenes_trabajo`, `inventario_repuestos` y `entradas_inventario` |
| KPIs precalculados | Tablas `kpis_activos_mensuales` y `kpis_tecnicos_mensuales` con métricas de disponibilidad, MTBF, MTTR y rendimiento |
| Alertas | Tabla `alertas` con soporte polimórfico para stock bajo, vencimiento de planes y otras notificaciones |
| Auditoría granular | Tabla `auditorias_cambios` con registro campo por campo |
| Configuración dinámica | Tabla `configuraciones_sistema` para parámetros clave-valor sin tocar código |
